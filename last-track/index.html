문제 1

복잡한 규칙을 설명하는 대신 지금의 선택을 이해하게

문제와 원인

세 행동을 계획하고 상대의 신호를 읽는 심리전에서는 무엇을 이미 확정했고 무엇을 아직 바꿀 수 있는지 알아야 합니다. 규칙이 바뀌었는데 안내 카피가 남아 있으면, 플레이어가 없는 기능을 기대하거나 현재 선택의 의미를 잘못 이해할 수 있습니다.

게임의 규칙·화면·서사 문장은 서로 다른 위치에서 바뀝니다. 제작 기록에는 규칙 변경 뒤 이전 행동 설명이 남은 사례가 있으며, 과거 기획과 실험 화면을 현재 본편 규칙처럼 읽는 위험도 있었습니다.

선택한 해결과 이유

팀의 현행 룰북은 여섯 행동과 첫 행동 잠금 → 신호 공개 → 나머지 두 행동 확정 → 동시 실행의 흐름을 기준으로 정리합니다. 제 담당 축인 시나리오·연출·카피에서는 공간의 상황과 안내 문장이 이 실제 순서와 같은 사건을 설명하도록 다뤘습니다. 과거 실험 규칙과 본편의 설명도 구분했습니다.

심리전의 긴장감은 규칙을 몰라서 생기는 혼란보다, 알고 있는 정보로 상대를 추론하는 데서 나와야 합니다. 서사와 카피도 장식이 아니라 현재 상태와 다음 행동을 이해시키는 인터페이스로 봤습니다.

감수한 점

콘솔과 환경 안에 설명을 배치하면 세계관은 이어지지만 작은 글자나 긴 연출이 판단을 방해할 수 있습니다. 설명을 줄이는 일과 필요한 정보를 남기는 일을 함께 다뤄야 하며, 신호를 설명하다 숨겨진 정보까지 확정적으로 말하지 않도록 주의해야 합니다.

확인한 근거

현행 룰북의 행동·공개 정보·작전 확정 순서, 협업 문서의 규칙 변경 후 카피 불일치 기록, 개인 역할 표의 시나리오·서사·연출·카피 담당에 근거합니다. 판정 엔진과 NPC 설계 전체를 개인 구현으로 표현하지 않습니다.

다음 확인

처음 플레이하는 사람이 첫 행동과 이후 두 행동의 차이, 상대 신호와 실제 비공개 계획의 차이를 자신의 말로 설명할 수 있는지 확인합니다. 도입부터 첫 결과까지 망설이거나 잘못 예측한 지점을 기록해 문장과 배치를 조정할 계획입니다.

문제 2

공포의 톤을 맞추면서 소리가 전달할 정보도 보존

문제와 원인

버려진 지하 공간의 긴장감을 의도했지만, 밝은 획득음과 승리 팡파르는 아케이드처럼 들린다는 제작 피드백이 있었습니다. 반대로 소리를 어둡게 통일하는 과정에서는 서로 다른 행동 결과가 비슷하게 들리는 문제도 드러났습니다.

기존 UI 소리는 화면의 성공·실패를 알리는 관습에 가까웠고 공간의 재질과 연결되지 않았습니다. 이후 소리 종류를 묶는 방향은 분위기를 정리했지만, 밀치기·자리 교환·경합처럼 구분해야 하는 사건의 정보까지 줄일 수 있었습니다.

선택한 해결과 이유

연출 방향을 금속 질감·노이즈·공통 공간 잔향으로 정리하고, 장조 팡파르 대신 질감과 정적의 변화로 결과를 표현하는 기준을 세웠습니다. 제작 과정에서는 다른 의미의 사건이 같은 소리로 뭉개지지 않도록 구분을 되살렸고, 붕괴가 가까워질수록 강도가 변하도록 조정하는 방향을 택했습니다. 이는 팀이 구현한 사운드 체계에 대한 연출 판단이며 전체 음향 코드를 개인 작업으로 주장하지 않습니다.

세계관에 맞는 소리와 읽을 수 있는 소리는 함께 성립해야 합니다. 무조건 더 많은 효과를 넣거나 항상 강하게 울리는 대신, 사건의 구분과 긴장도의 변화를 통해 판단을 돕는 소리를 지향했습니다.

감수한 점

일관된 음색은 장소감을 주지만 사건별 차이를 약하게 만들 수 있고, 강한 공포음은 반복 플레이에서 피로와 정보 가림을 만들 수 있습니다. 무음이나 소리를 듣기 어려운 환경에서도 필요한 정보가 화면으로 전달되어야 합니다.

확인한 근거

2026.08.21 사운드 방향 문서와 2026.08.23 본편 반영 기록, 아케이드처럼 들린다는 제작 피드백, 사건별 소리 구분 복원과 긴장도 조절 기록에 근거합니다. 정식 사용자 연구나 몰입도 향상 수치로 해석하지 않았습니다.

다음 확인

같은 사건을 들려주고 어떤 결과인지 구분하는지, 반복할수록 소리가 피곤하거나 선택을 가리는지 확인합니다. 소리만·화면만·함께 제시하는 비교는 후속 검증안이며, 이번 정리에서 이미 수행한 실험은 아닙니다.

문제 3

여러 장면에 흩어진 이야기가 서로 다른 말을 하지 않도록

문제와 원인

도입·탐색·콘솔·결과와 검토용 화면이 늘어나면서 같은 이야기의 문장을 여러 곳에 복사해 관리하기 쉬워졌습니다. 한쪽만 수정되면 본편과 검토 화면이 다른 내용을 보여주거나, 아직 확정하지 않은 문장이 노출될 수 있었습니다.

시나리오 설정과 실제 표시 문장이 코드와 문서 여러 곳에 흩어져 있었습니다. 제작 기록에는 자막의 중복 보관과 검토 화면의 문구 복사로 변경이 어긋난 사례가 남아 있습니다. 설정 정리 문서를 만든다는 것만으로 실제 화면 문장의 기준이 하나가 되지는 않았습니다.

선택한 해결과 이유

시나리오 취합 문서는 세계·인물·흐름과 원문의 위치를 연결하는 지도로 사용하고, 실제 표시 문장을 다시 복사해 새로운 기준으로 만들지 않는 방향을 정리했습니다. 확정된 문구의 상태와 소유 위치를 구분하고, 본편과 연출 검토 화면도 역할을 나눴습니다. 개인 담당은 시나리오·서사·카피·영상 축이며 승인 처리와 전체 시스템 구현은 공동 작업의 범위입니다.

이야기의 일관성은 문장을 잘 쓰는 것뿐 아니라 어느 문장을 언제 화면에 보여줄지 관리하는 문제이기도 합니다. 문서·검토 화면·플레이 영상이 실제 본편과 같은 근거를 바라봐야 제작 의도를 설명하는 자료도 신뢰할 수 있습니다.

감수한 점

표시 문장의 기준을 분리해 관리하면 변경 위치는 명확해지지만, 관련 장면과 언어·노출 상태를 함께 검토하는 절차가 필요합니다. 검토 화면에서 한 장면이 좋아 보이더라도 본편의 연결과 진행 상태가 검증된 것은 아닙니다.

확인한 근거

2026.08.25 시나리오 취합 문서에 기록된 분산·복사·검토 화면의 문면 불일치 사례와 원문 위치 참조 원칙, 본편과 실험 화면을 구분한 협업 기록에 근거합니다. 해당 취합 문서 자체도 승인 대기 지위를 명시하므로 확정된 시나리오 정본이라고 소개하지 않습니다.

다음 확인

일반 진입에서 도입 → 탐색 → 첫 작전 → 결과 → 단서로 이어지는 문장과 상태를 확인합니다. 반복 진입·새로고침·결과 이후에도 문맥이 이어지는지 살피며, 검토용 화면의 통과와 전체 경험의 완료를 별도로 기록합니다.

프로젝트의 동작·설계 근거와 실제 사용 효과는 구분해 설명합니다.

03 / DESIGN DECISIONS

01

서사는 게임의 앞뒤를 연결

기억 복도와 벙커 탐색을 통해 게임의 상황을 제시하고, 패배·탈출 이후에도 장면과 단서가 이어지도록 구성했습니다.

경험의 기준도입 영상만 보는 경험에서 공간을 직접 지나고 사물에 반응하는 경험으로 연결합니다.
02

콘솔을 판단의 중심으로

중앙 화면에는 작전과 판정을, 좌우 계기에는 호흡·최근 행동·상대의 자세 신호를 배치했습니다. 상태 정보가 공간의 장치로 보이도록 구성했습니다.

정보의 역할무엇이 공개됐고 무엇이 아직 보이지 않는지 구분하며, 현재 선택과 결과의 관계를 읽게 합니다.
03

소리의 톤도 같은 세계관으로

밝은 정답음이나 승리 팡파르 대신 금속 질감·노이즈·공통 잔향을 기준으로 음향 방향을 정리했습니다. 결과는 공간의 정적과 질감 변화로 전달합니다.

연출의 기준화면과 분리된 UI 효과음보다 버려진 지하 공간 안에서 발생하는 소리로 묶습니다.
04

본편과 연출 랩을 구분

실제 플레이 본편은 루트 주소 하나입니다. 연출·소리·콘솔·엔딩 등을 따로 확인하는 랩을 두고, 결정·검수·실험·측정·보관의 목적별로 나눴습니다.

제작 과정랩의 실험을 현재 게임 규칙으로 혼동하지 않으며, 장면별로 반복 확인할 수 있게 합니다.

시나리오와 경험의 연결

게임의 배경과 진행 맥락을 정리하고, 도입·탐색·대전·결과가 하나의 경험으로 이어지는 방향을 다뤘습니다.

연출과 안내 카피

서사 톤과 장면의 흐름, 플레이어에게 전달하는 문장과 음향 방향을 함께 검토하는 담당 축입니다.

플레이 영상과 전달

게임을 실제로 어떻게 경험하는지 보여주는 플레이 영상과 소개 자료를 통해 제작 의도와 결과물을 연결합니다.

구분공개 포트폴리오에서의 표현
개인 담당의 큰 축시나리오·서사·연출·카피·플레이 영상. 역할 분담 문서 기준이며 모든 관련 파일의 단독 제작을 뜻하지 않습니다.
팀 전체 구현판정 엔진·NPC·밸런스·3D UI·온라인 대전·배포와 운영. 서로의 작업을 함께 보완하는 협업 구조였습니다.
AI 도구 활용조사·설계 대안·코드와 자산 제작·검증을 보조했습니다. 생성된 결과의 검토와 방향 결정은 작업자의 책임으로 두었습니다.

개인별 기여율이나 작업량 비중은 계산하지 않았습니다. 행사 참여 사실 외에 수상·순위·사용자 수를 주장하지 않습니다.

영역담당하는 동작연결 방식
플레이와 장면React·TypeScript 화면과 Three.js 3D 공간진행 상태를 기준으로 카메라·콘솔·상호작용·장면을 연결합니다.
공용 경기 진행행동 잠금·동시 공개·작전 수정·판정순수 판정 로직과 진행기를 분리하고 UI가 공개 상태를 소비합니다.
상대와 대전솔로 NPC, 서버 권위 온라인 두 좌석 경기공개 정보와 비공개 계획을 구분하며 각 좌석의 관측 범위를 나눕니다.
호스팅과 기록Cloudflare Workers·D1, 경기 기록 집계운영판과 개발판의 경로·저장 공간·플레이 기록을 구분합니다.
제작·검수 랩콘솔·사운드·시네마틱·엔딩·성능 확인하나의 장면을 따로 조작해 검토하고 본편과 실험 자료를 구별합니다.
