# 문제·해결 설명과 면접 노트 수정

각 프로젝트 JSON 하나가 공개 사례의 ‘문제 정의·해결 판단’ 영역과 면접 설명 노트의 원본입니다. 기존 스크린샷·로고·나머지 사례 본문은 유지합니다.

## 수정할 파일

- `index.json`: 프로젝트 이름·분류·노트 목록·수정일.
- `mailwork.json`, `wiki-chatbot.json`, `visitor-system.json`, `mj-dashboard.json`, `glgym.json`, `what-the-hatch.json`, `last-track.json`: 각 프로젝트의 설명 원문.

`publicSections`는 문제, 원인, 선택한 해결, 이유, 감수한 점, 확인 근거, 다음 검증을 담습니다. 이미 검증한 결과와 앞으로 검증할 항목을 구분합니다.

`interview`는 1분 설명, 3분 설명 순서, 예상 질문·답변, 역할 확인, 후속 자료 목록을 담습니다. 개인 담당·개발 기간·정량 성과가 확인되면 실제 증빙을 기준으로 보완합니다. 팀 전체 구현을 개인의 단독 기여로 바꾸지 않습니다.

기존 설명이 과거 기록에 기반했다면 근거 시점을 유지하고, 현재 내용과 달라진 부분을 구분해 수정합니다. 절대 로컬 경로·내부 접속 주소·비공개 자료 원문은 공개 설명에 넣지 않습니다.

## HTML에 반영

저장소 루트에서 실행합니다. Python 표준 라이브러리만 사용합니다.

```sh
python tools/render-explanations.py
```

도구는 `portfolio:reasoning` 주석 사이의 본문, `interview/` 아래의 준비 노트, 홈의 준비 노트 연결, 사이트맵을 갱신합니다. 기존 사례의 화면·로고·다른 본문은 덮어쓰지 않습니다. 생성한 HTML만 직접 고치면 다음 실행 시 해당 생성 영역이 다시 바뀌므로 이 JSON을 먼저 수정합니다.

홈의 프로젝트 순서는 이 도구가 변경하지 않습니다.

## 면접 준비 방식

1. 1분 설명을 실제로 말하며 길이를 조절합니다.
2. 3분 설명 순서를 사례의 화면·근거와 연결합니다.
3. ‘답변 가리고 연습하기’로 질문에 먼저 답한 뒤 초안과 비교합니다.
4. 개인 역할·팀 역할·검증 범위를 본인의 기록으로 확정합니다.
5. 프로젝트별 노트를 브라우저의 인쇄 / PDF 기능으로 보관할 수 있습니다.
