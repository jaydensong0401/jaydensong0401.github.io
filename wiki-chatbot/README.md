# Wiki-ChatBot 포트폴리오 페이지 개편 기획서

개편 기준일: 2026-11-09  
대상 페이지: `/wiki-chatbot/`  
공개 주소: <https://jaydensong0401.github.io/wiki-chatbot/>

## 1. 개편 목적

방문자가 첫 화면에서 실제 서비스의 모습과 이용 목적을 이해하도록 한다. 기존의 ‘이 혜택을 적용할 수 있는가’에 치우친 소개를 확장해, 제네시스 정책을 질문하고 근거와 함께 정리하며 변경 사항을 관리하는 사내 업무 시스템으로 설명한다.

상단에는 실제 서비스의 비식별 화면 캡처를 배치한다. 본문의 핵심 흐름인 **작업 방식 → 답변 구조 → 운영 방식**은 유지한다. 서비스의 이용자, 다루는 정책, 질문과 답변의 기준, 정책 변경의 책임이 이 순서 안에서 자연스럽게 이어지도록 구성한다.

## 2. 서비스 정의와 사용자

**Wiki-ChatBot은 사내 임직원이 제네시스 전 차종의 혜택 오퍼링·프리빌리지·기프트 정책을 질문하고, 관련 근거를 확인하며 정책을 정리하는 사내 전용 질의응답 및 정책 정리 시스템이다.**

여기서 ‘사내 임직원’은 시스템의 이용자를 뜻한다. ‘임직원 전용 할인 혜택’으로 서비스 범위를 좁혀 설명하지 않는다. 차종·연식·기준일과 정책 유형에 따라 달라지는 정보를 업무 맥락에서 찾아보고 정리하는 것이 핵심이다.

| 사용자 | 필요한 일 | 페이지에서 설명할 경험 |
| --- | --- | --- |
| 사내 임직원 | 혜택 오퍼링·프리빌리지·기프트의 구성과 관련 정책 확인 | 질문 입력, 질문 범위 지정, 답변과 출처 확인, 필요한 답변 저장 |
| 정책을 정리하는 담당자 | 새 자료와 정책 변경 사항 제안 | 자료 등록·수정 제안, 적용 대상과 기간 정리, 검토 상태 확인 |
| 관리자 | 변경 자료의 검토와 답변 반영 관리 | 검토·승인·수정 요청, 적용일 확인, 원본·현재 적용본·변경 이력 확인 |

전 차종은 서비스가 다루는 업무 범위의 정의다. 모든 차종·정책 질문에 대한 답변 정확도나 자료 완전성을 검증했다는 의미로 사용하지 않는다.

## 3. 핵심 메시지와 문구 원칙

첫 화면에서 ‘누가, 무엇을 물어보고, 어떤 방식으로 정리하는 서비스인지’를 함께 전달한다.

- 서비스명: Wiki-ChatBot
- 서비스 분류: 사내 전용 질의응답 · 정책 정리
- 핵심 소개: 제네시스 전 차종의 혜택 오퍼링·프리빌리지·기프트 정책을 사내 임직원이 질문하고, 조건과 근거를 확인하며 정리하는 시스템
- 설명의 중심: 단순한 혜택 적용 가능 여부를 넘어 정책 구성·대상·기간·관련 자료·변경 사항의 확인

‘질문’, ‘답변’, ‘정책 정리’, ‘근거’, ‘적용 조건’을 구체적으로 사용한다. ‘혜택 적용’은 실제 정책의 적용 조건을 설명할 때에만 사용한다. 업무 질문의 예시는 특정 정책의 진위를 주장하지 않는 일반적인 형태로 작성한다. 예를 들어 ‘차종·연식별 프리빌리지 구성을 정리해 줘’와 같이 기능의 사용 목적을 설명한다.

## 4. 페이지 구성

| 순서 | 영역 / 식별자 | 전달할 내용 | 화면과 구성 |
| --- | --- | --- | --- |
| 최상단 | 실제 서비스 화면과 소개 | 실제 화면을 먼저 보여 주고 서비스 정의와 이용자를 명시 | 비식별 답변 화면을 넓게 배치하고 캡처 설명·확대 동작 제공 |
| 01 | 작업 방식 / `#work` | 정책을 질문하고 정리하기까지의 업무 흐름 | 질문 → 범위 확인 → 관련 자료 확인 → 답변·정리 → 저장·후속 확인, 질문 범위 화면 |
| 02 | 답변 구조 / `#answer` | 답변을 판단할 때 필요한 조건과 근거 | 정책 내용·대상·기간·출처·버전의 관계 |
| 03 | 운영 방식 / `#operations` | 정책 변경과 실제 답변 반영의 책임 | 자료 제안 → 관리자 검토 → 승인·적용일 확인 → 이후 답변 반영, 검토 화면 |
| 04 | 검증 범위 / `#scope` | 구현한 기능과 앞으로 확인할 품질을 구분 | 현재 기능, 독립 업무 질문 평가·운영 검증 과제 |
| 하단 | 과거 참고 자료 / `#gallery` | 기존 기획 기록을 필요할 때 열람 | 2026-10-26 작성한 소개 자료 8장을 닫힌 펼침 영역으로 보관 |

페이지 안의 이동 링크는 `#work`, `#answer`, `#operations`, `#scope`에 연결한다. 위 세 본문 영역은 작업 방식 → 답변 구조 → 운영 방식 순서로 유지하고, 기존 소개 슬라이드가 이 흐름보다 먼저 나오지 않도록 한다.

### 작업 방식: 질문을 업무 자료의 정리로 연결

사내 임직원이 자연어로 질문하고 필요할 때 차종·연식·기준일을 지정한다. 모호하거나 충돌하는 조건은 추가 확인으로 좁힌다. 관련 자료를 선택하고 연결된 정책을 함께 확인한 뒤, 근거가 있는 답변과 정책 내용을 정리한다. 필요한 답변은 개인 저장 목록과 기존 대화에서 다시 확인할 수 있다.

이 영역은 기능 목록보다 사용자의 실제 행동을 중심으로 설명한다. 정책 자료가 흩어져 있고, 같은 주제도 대상과 시점에 따라 달라져 다시 확인해야 한다는 업무 문제를 연결한다.

### 답변 구조: 내용·조건·근거를 함께 확인

혜택 오퍼링·프리빌리지·기프트의 관련 내용을 정책별로 정리하되 차종·연식·기준일과 적용 기간을 함께 설명한다. 자료가 부족하거나 조건을 확정할 수 없으면 확인이 필요한 부분을 드러낸다.

답변에 사용한 출처와 당시 수정 버전·검토 상태를 연결한다. 저장한 답변도 당시의 답변과 근거를 보존하므로 현재 정책과 과거 답변의 기준을 구분해서 설명한다. 표 형태의 정리는 정보를 비교하고 확인하기 위한 답변 표현의 하나로 소개한다.

### 운영 방식: 제안과 승인, 적용 시점을 구분

신규·수정 자료는 임시 저장과 등록을 거쳐 관리자 검토 대상으로 보낸다. 승인 대기 자료는 현재 답변에 바로 반영하지 않으며, 관리자가 내용·적용 대상·기간을 확인해 승인하거나 수정을 요청한다.

승인과 시행은 서로 다른 조건이다. 미래 시작일의 승인본은 시작일부터 답변 근거로 사용하고, 만료된 자료를 과거 버전으로 자동 대체하지 않는다. 원본·현재 답변 적용본·변경 이력을 구분해 관리한다. 기존 대화의 답변과 근거는 당시 상태로 보존한다.

최초 수입한 미검토 원본은 상태를 안내하며 검색에 사용될 수 있다. 따라서 ‘모든 답변은 승인된 자료만 사용한다’고 설명하지 않는다.

원본은 2026-10-21 제작한 공개용 비식별 실제 PC 캡처다. 이미지 자체에 민감정보 가림 처리 안내가 포함되어 있다. 이를 가상 데이터 데모나 새로 만든 시안으로 설명하지 않는다.

계정·개인정보·실제 질문과 답변·자료명·정책 상세·내부 적용 정보를 가린 공개용 파일을 사용한다. 원래 픽셀을 불투명 영역으로 교체한 파일만 게시하고 가림 전 캡처를 저장소에 넣지 않는다. 원본 사내 접속 주소, 계정명, 정책 원문은 페이지와 기획서에 기재하지 않는다.

캡처에는 무엇을 보여 주는지 설명하는 대체 텍스트와 캡션을 제공한다. 상단 이미지는 바로 불러오고, 보조 이미지는 필요할 때 불러온다. 이미지의 비율을 유지하고 PC·모바일에서 내용을 임의로 잘라내지 않는다. 기존 이미지 확대 기능과 키보드 접근을 유지한다.

## 6. 기존 소개 슬라이드의 역할

기존 `pm-case-study_01.png`부터 `pm-case-study_08.png`까지의 자료는 2026-10-26 작성된 예시 데이터 기반 설명 자료다. 실제 서비스 화면과 구분하고, 페이지 하단의 기본적으로 닫힌 과거 참고 자료 영역에만 둔다.

과거 자료에 포함된 표현·검증 수치·날짜는 당시 기록의 범위로 안내한다. 이번 개편의 서비스 정의나 최신 성과를 대신 설명하는 대표 자료로 사용하지 않는다. 과거 ‘혜택 적용’ 중심 문구가 담긴 슬라이드를 상단 대표 이미지로 재사용하지 않는다.

## 7. 기술 및 검증 정합성

- 구현 기술은 기존 설명과 같이 FastAPI · Next.js · SQLite · Ollama를 기준으로 소개한다.
- 현재 원장 검색은 식별자 일치·어휘/BM25·조건 필터·관계 자료 연결을 사용한다. 의미 기반 벡터 검색이나 모델 학습을 현재 구현 성과로 추가하지 않는다.
- 기간·연식 등 명확한 조건의 답변은 규칙 기반으로 처리하고, 일반 질문에는 근거를 연결한 로컬 LLM 답변을 사용한다. 모든 답변을 LLM이 생성한다고 표현하지 않는다.
- 일반 사용자의 개인 대화·저장 답변과 관리자 검토·승인 기능의 책임을 구분한다.
- 자료 검토와 질문 수집이 자동으로 모델을 학습시키거나 정책을 승인한다는 표현을 사용하지 않는다.
- 기능 구현·기존 검사 기록과 실제 업무 답변 품질은 구분한다. 확인하지 않은 정확도·업무시간 절감·비용 개선 수치, 전사 도입 완료, SSO 또는 공개 서비스 운영 완료를 주장하지 않는다.

검증 범위 영역에는 질문 범위·근거·버전 연결, 자료 제안·검토·승인·적용일, 저장 답변의 근거 보존을 현재 소개 범위로 제시한다. 독립적인 업무 질문 평가, 잘못된 근거 선택·기간 예외, 정정 빈도, 인증·백업·복구·배포 검증은 추가 확인할 내용으로 설명한다.

기능 사실은 서비스의 README, ARCHITECTURE, STATUS와 공개용 캡처 설명을 함께 대조한다. 과거 개발 계획의 일정과 검증 수치를 이번 개편에서 새로 실행한 결과로 옮기지 않는다.

## 8. 반영 완료 기준

1. 첫 화면에 설명 슬라이드 대신 실제 비식별 답변 화면이 보인다.
2. 서비스 이용자가 사내 임직원이며, 다루는 범위가 제네시스 전 차종의 혜택 오퍼링·프리빌리지·기프트 정책임을 소개와 메타 설명에서 확인할 수 있다.
3. 본문의 작업 방식 → 답변 구조 → 운영 방식 순서와 `#work`, `#answer`, `#operations`, `#scope` 이동이 유지된다.
4. 답변 내용뿐 아니라 조건·근거·당시 버전과 정책 검토·적용 시점을 함께 설명한다.
5. 세 캡처의 경로·대체 텍스트·캡션·확대 동작과 모바일 이미지 표시를 확인한다.
6. 기존 8장 슬라이드는 하단의 닫힌 참고 자료에만 남고, 과거 설명 자료라는 안내가 붙는다.
7. 미검토 원본의 사용 가능성, 규칙과 LLM의 역할, 현재 검색 방식에 대한 설명이 구현 사실과 일치한다.
8. 공개 파일과 문서에 사내 주소·계정·정책 원문이 없으며, 이번에 수행하지 않은 품질 검증을 완료로 표현하지 않는다.

이 문서는 공개 포트폴리오의 구성과 문구를 위한 개편 기획서다. 서비스 자체의 정책·운영 데이터나 기능을 변경하는 작업은 포함하지 않는다.
