01 / PROBLEM

답을 찾은 뒤에도,
적용 조건을 판단해야 했습니다.

자료가 있다는 사실과 현재 질문에 그 자료를 적용할 수 있다는 판단은 다릅니다.

같은 질문, 달라지는 조건

차종·연식·기준일이 달라지면 같은 혜택이나 규칙도 다르게 적용될 수 있습니다. 질문의 범위를 먼저 정하고, 범위가 맞는 자료를 선택하도록 구성했습니다.

변경된 정책과 답변의 일치

새 정책이 작성됐다는 이유만으로 즉시 답변에 적용해서는 안 됩니다. 검토 상태와 적용 기간, 수정 버전을 검색·승인·답변의 공통 기준으로 연결했습니다.

02 / KEY DECISIONS

답변을 만드는 흐름과
답변을 확인하는 기준을 함께.

기능을 늘리는 것보다 어떤 조건에서 어떤 근거를 사용하는지 명확히 하는 데 중심을 둔 설계입니다.

01

질문의 조건을 먼저 정리

차종·연식·기준일을 질문 범위로 받고, 조건이 모호하거나 충돌하면 확인 질문으로 좁힙니다.

설계 판단넓은 답변을 바로 생성하기보다 적용 범위를 확인하는 흐름을 우선했습니다.
02

출처의 버전과 상태를 표시

답변의 근거 자료와 당시 수정 버전·검토 상태를 함께 보여 주고 저장한 답변에도 당시 출처를 보존합니다.

사용자 판단생성된 문장만 읽는 것이 아니라 근거의 상태와 시점을 확인할 수 있도록 구성했습니다.
03

승인과 적용 시점을 구분

신규·수정 정책은 검토·승인을 거쳐 반영합니다. 승인됐어도 적용 시작일이 미래라면 현재 답변의 근거로 사용하지 않습니다.

운영 규칙기존 미검토 원본은 상태를 표시하며 사용될 수 있습니다. 모든 자료가 승인본인 것으로 표현하지 않습니다.
04

정형 판단과 LLM의 역할 분리

기간·연식처럼 조건이 명확한 판단은 규칙으로 처리하고, 일반 질문에는 적격 근거를 연결해 로컬 LLM의 답변을 구성합니다.

기술 선택현재 원장 검색은 코드 일치·BM25·조건 필터·관계 연결을 사용합니다. 의미 기반 벡터 검색이 구현된 것으로 설명하지 않습니다.
03 / WORKFLOW

질문부터 근거 확인,
변경 검토까지 이어지는 흐름.

사용자는 질문과 출처를 확인하고, 관리자는 변경된 자료의 적용 기준을 관리합니다.

01

질문과 조건

대상과 기준일을 함께 정합니다.

02

적격 자료 선택

검토 상태와 적용 기간을 확인합니다.

03

근거 연결

현재 버전과 관련 정책을 결합합니다.

04

답변과 출처

응답과 당시 근거를 함께 남깁니다.

05

검토와 변경

정책 제안·승인·이력으로 이어집니다.

변경된 정책은 답변에 언제 반영되는가?임시 저장 → 승인 대기 → 관리자 검토 → 승인·적용일 확인 → 다음 질문의 근거 반영. 기존 대화의 답변과 근거는 당시 상태로 보존합니다.
