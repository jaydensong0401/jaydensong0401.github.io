문제 1

찾은 문장이 어떤 정책의 조건인지 잃지 않도록

문제와 원인

사내 임직원이 정책을 질문할 때는 문장 하나를 찾는 것보다 어떤 차종·연식·기간·서비스에 속한 내용인지 확인하는 일이 중요합니다. 혜택, 조건, 옵션, 바우처, 회차와 일정이 떨어져 있으면 제목이 비슷한 다른 항목이 섞이거나 적용에 필요한 조건이 답변에서 빠질 수 있습니다.

엑셀의 긴 내용을 글자 수만으로 자르면 값은 남아도 필드명과 상위 항목의 관계를 잃기 쉽습니다. 이름이 같은 항목을 하나로 합치거나 상위 문서의 복사된 과거 내용을 현재 정책으로 사용해도 정리된 답변의 신뢰가 떨어집니다.

선택한 해결과 이유

원장 전처리에서는 고유 ID를 가진 업무 레코드와 관계를 먼저 정리하고 값을 ‘필드명: 값’으로 표현합니다. 긴 필드는 1,200자 단위로 나누며 필드명을 반복하고, 약 1,700자를 기준으로 필드를 묶을 때 공통 문맥과 확인사항을 함께 보존합니다. 출처·부모 ID·차종·연식·기간·상태와 변경 해시도 관리합니다.

검색에 쓰는 단위가 작아져도 ‘이 조건은 무엇에 속하는가’를 되짚을 수 있도록 하는 선택입니다. 단순히 더 많은 조각을 만드는 것이 아니라 업무 레코드의 식별과 관계를 유지하는 전처리 기준을 설명할 수 있습니다.

감수한 점

관계와 메타데이터를 보존하면 전처리 규칙과 변경 영향 관리가 복잡해집니다. 연결이 모호한 항목을 임의로 합치지 않고 확인 대상으로 남겨야 합니다. 또한 1,200·1,700은 문자 수의 분할·묶음 기준이지 최종 청크의 엄격한 최대 길이나 토큰 수가 아닙니다.

확인한 근거

현재 포트폴리오의 엑셀 청킹 설명과 원장 처리 구조에서 ID·필드명·관계·메타데이터 보존을 확인할 수 있습니다. 이 전처리 설명을 현재 답변 검색이 생성된 청크 파일의 벡터 검색으로 동작한다는 뜻으로 사용하지 않습니다.

다음 확인

같은 이름의 다른 정책, 상위 항목을 공유하는 옵션, 긴 조건문, 관계가 모호한 원장을 가상 사례로 만들어 출처와 적용 조건을 되짚을 수 있는지 확인할 필요가 있습니다. 전처리 결과의 구조적 완전성과 답변 품질은 각각 평가해야 합니다.

문제 2

관련 있어 보이는 자료와, 지금 적용할 수 있는 자료를 구분

문제와 원인

같은 질문도 대상 차종·연식·기준일에 따라 답이 달라질 수 있습니다. 질문과 단어가 비슷한 자료를 찾았다는 이유만으로 답하면 다른 대상의 조건이나 아직 시행되지 않은 정책을 현재 기준처럼 안내할 위험이 있습니다.

문서의 관련도, 검토 상태, 적용 기간, 수정 버전을 서로 다른 기준으로 처리하면 답변에 쓸 자료를 고르는 단계에서 불일치가 생깁니다. 현재 자료가 없다고 과거 버전을 자동으로 가져오거나, 저장한 과거 답변의 근거를 새 버전으로 바꿔도 당시 판단을 설명하기 어려워집니다.

선택한 해결과 이유

현재 원장 답변 경로는 DB의 적용 가능한 수정본을 기준으로 코드·식별자 일치, 어휘/BM25, 차종·연식·기간 조건과 관련 자료 연결을 사용합니다. 모호하거나 충돌하는 질문 범위는 확인하고, 답변과 저장한 응답에는 당시 근거의 버전과 상태를 연결합니다. 만료된 자료를 과거 버전으로 자동 대체하지 않습니다.

관련도 순위보다 먼저 ‘이 질문에 사용해도 되는 자료인가’를 관리하면 내용 생성과 정책 적용의 책임을 구분할 수 있습니다. 답변 이후에도 어느 시점의 어떤 근거를 사용했는지 확인할 기준이 남습니다.

감수한 점

조건을 엄격히 적용하면 답변 후보가 줄고 추가 확인이 필요할 수 있습니다. 어휘·코드 중심 검색은 출처와 상태를 관리하기 쉽지만 새로운 표현이나 별칭을 놓칠 수 있습니다. 별도의 벡터 검색 구성요소가 존재한다는 사실과 이 사례의 현재 원장 검색 경로는 구분합니다.

확인한 근거

질문 범위 화면, 답변의 출처·수정 버전 표시, 저장 답변의 근거 보존과 수정본 기준의 원장 검색 코드를 함께 근거로 삼을 수 있습니다. 기존 미검토 원본은 상태를 안내하며 사용될 수 있어 ‘모든 답변은 승인 자료만 사용한다’고 설명하지 않습니다.

다음 확인

미래 시행·기간 만료·불명확한 연식·차종 충돌·동일 이름의 다른 정책·유사 표현 질문을 독립 문항으로 만들고, 답변 문장보다 먼저 선택한 근거가 적격했는지를 평가해야 합니다. 정답을 내지 않고 추가 확인해야 하는 사례도 평가 대상입니다.

문제 3

정책을 작성한 사실과, 답변에 반영해도 되는 시점을 분리

문제와 원인

새 정책이나 수정안이 생길 때 작성한 내용이 곧바로 현재 답변의 근거가 되면 검토되지 않은 조건이나 미래 시행 내용을 사용자에게 안내할 수 있습니다. 누가 입력하고 누가 확인하며 언제부터 사용하는지를 서비스 안에서 구분하는 것이 세 번째 문제였습니다.

원본 자료, 작성 중인 변경, 현재 답변 적용본과 과거 이력이 한 상태로 취급되면 초안을 보여 주거나 기존 정책을 조용히 덮어쓸 수 있습니다. 승인만 확인하고 시행일을 보지 않거나, 날짜를 모르는 상태를 확정값처럼 처리해도 같은 문제가 생깁니다.

선택한 해결과 이유

정책 추가에서 제목·내용·적용 차종·연식·기간을 입력하고 임시 저장과 정보 등록을 구분합니다. 등록한 신규·수정 자료는 관리자 검토 대상으로 보내며, 관리자가 내용·대상·기간을 확인한 뒤 승인하거나 수정을 요청합니다. 승인과 적용일을 함께 확인하고 원본·현재 적용본·변경 이력을 구분합니다. 날짜가 불명확하면 확인 전 승인·답변 반영을 막습니다.

작성과 검토, 시행의 책임을 나누면 입력 편의와 답변의 신뢰 기준을 함께 다룰 수 있습니다. 기존 대화는 당시 답변과 근거를 보존하므로 새 정책 반영과 과거 답변의 설명 가능성도 분리됩니다.

감수한 점

검토 단계는 즉시 반영보다 느리며 담당자의 운영 부담이 생깁니다. 파일 가져오기와 본문 전체 교체처럼 편리한 입력 방식에는 적용 범위 누락 위험도 있어 등록 전 확인이 필요합니다. 이 책임 분리는 확인된 구현 기준이며 모든 운영 실수나 승인 오류가 해결됐다는 뜻은 아닙니다.

확인한 근거

정책 추가 패널과 정책 관리 화면에서 임시 저장·정보 등록·관리자 승인·수정 요청 흐름을 확인할 수 있습니다. 정책 추가 화면은 선택적으로 UTF-8 MD/TXT 본문을 가져오는 기능이며 엑셀 직접 업로드나 자동 정책 승인으로 설명하지 않습니다.

다음 확인

동시 수정, 중복 승인, 미래 시행일 도달, 날짜 미확정, 수정 요청 후 재등록, 과거 저장 답변 열람을 하나의 운영 시나리오로 검증해야 합니다. 검토 리드타임과 정책 정정 빈도는 실제 운영 기록이 있어야 측정할 수 있습니다.

프로젝트의 동작·설계 근거와 실제 사용 효과는 구분해 설명합니다.

EXCEL → KNOWLEDGE LEDGER → CHUNKS

엑셀의 업무 맥락을 유지하는 청킹

엑셀의 혜택명·적용 차종·기간·예외 조건이 함께 검색될 수 있도록, 고유 ID가 있는 업무 레코드를 기본 단위로 삼았습니다. 여기서 청킹은 긴 데이터를 검색에 사용할 작은 단위로 나누는 전처리입니다.

01 / 원본엑셀 데이터

혜택·조건·옵션·회차·일정과 원본 위치

02 / 정리업무 레코드·지식 원장

고유 ID·필드·적용 조건·관련 항목 연결

03 / 전처리 결과청크 + 부모 문서

검색할 작은 단위와 상세 맥락을 함께 보존

RECORD

업무 항목과 고유 ID로 구분

이름이 같아도 차종·연식·조건이나 고유번호가 다르면 별도 항목으로 유지합니다. 서비스–옵션–바우처–회차–일정의 관계는 ID와 코드로 연결합니다.

이유서로 다른 혜택의 조건이 한 검색 단위에 섞이는 것을 줄이기 위해서입니다.

FIELD · 1,200자

긴 필드를 나누고 필드명 반복

각 필드를 ‘필드명: 값’으로 만듭니다. 긴 값은 1,200자씩 나누되 모든 조각에 필드명을 다시 붙여 어떤 내용인지 알 수 있게 합니다.

이유분할된 본문만 찾더라도 ‘적용 조건’인지 ‘제공 내용’인지 문맥을 잃지 않도록 했습니다.

GROUP · 약 1,700자

필드 단위로 묶고 공통 문맥 부착

필드 조각을 약 1,700자 기준으로 묶은 뒤 레코드의 공통 문맥과 확인사항을 붙입니다. 두 수치는 문자 수 기준이며, 최종 청크 길이는 공통 문맥을 더하면 1,700자를 넘을 수 있습니다.

이유긴 레코드를 작은 검색 단위로 나누면서 필드의 의미와 공통 조건을 함께 남기기 위한 기준입니다.

CONTEXT · TRACE

출처·관계·변경 이력 보존

각 청크에 원본 위치, 레코드·부모 ID, 차종·연식·기간·검토 상태와 관련 ID를 유지합니다. 상위 서비스가 하나인 종속 항목은 부모와 연결하고, 내용·연결 문맥의 해시로 변경 영향을 추적합니다.

이유검색한 조각에서 원문과 관련 조건으로 돌아가고, 공통 조건 변경 시 함께 갱신할 자료를 찾기 위해서입니다.

전처리 설계와 현재 답변 검색의 연결위 청킹은 엑셀 기반 원장을 검색 자료로 정리하는 전처리입니다. 현재 서비스는 DB에서 적용 가능한 수정본을 고른 뒤 코드 일치·BM25·조건 필터·관계 자료 연결로 검색합니다. 생성한 청크 파일을 그대로 벡터 검색하는 구조로 소개하지 않습니다.

구현 근거: 원장 갱신 도구의 청크 생성 규칙, 원장 DB 수입 로직, 현재 검색 서비스와 ARCHITECTURE 문서. 1,200자·약 1,700자는 현재 전처리의 설정 기준이며, 모든 업무에 대한 최적값을 검증한 수치는 아닙니다.

02 / 답변 구조

정책 내용과 적용 조건,
확인할 근거를 함께 보여줍니다.

임직원이 답변을 업무에 활용할 수 있도록 질문의 범위, 관련 정책, 출처와 당시 버전을 연결했습니다.

01

혜택과 정책을 읽기 쉽게 정리

질문에 맞는 혜택 오퍼링·프리빌리지·기프트 정보를 정리합니다. 항목을 비교하거나 여러 내용을 안내할 때는 표 형태로 보여줍니다.

답변의 역할자료를 찾은 뒤 다시 정리해야 하는 내용을 임직원의 질문 맥락에 맞춰 제시합니다.
02

차종·연식·기간을 답변과 연결

조건이 명확한 정책 판단은 규칙으로 처리하고, 일반 질문은 해당 조건에 맞는 자료를 연결해 로컬 LLM의 답변을 구성합니다.

검색 기준코드 일치·BM25·조건 필터·관계 자료 연결을 사용합니다. 질문 범위와 적용 기간을 함께 확인합니다.
03

출처의 상태와 버전 확인

어떤 자료를 근거로 답했는지, 당시 수정 버전과 검토 상태가 무엇인지 함께 보여줍니다. 자료가 미검토 원본이면 그 상태도 표시합니다.

임직원의 확인정리된 답변에서 근거 자료로 이어져, 정책의 내용과 적용 시점을 다시 확인할 수 있습니다.
04

저장한 답변에 당시 근거 보존

대화와 저장한 답변에는 응답 당시의 내용과 출처를 함께 남깁니다. 이후 정책이 바뀌어도 기존 답변의 근거를 확인할 수 있습니다.

지식의 축적개인의 대화·저장 답변과 공통 정책의 변경 이력을 구분해 관리합니다.
질의응답과 정책 정리를 하나의 경험으로임직원은 질문하고 근거를 확인한 뒤 답변을 저장합니다. 추가하거나 수정할 정책은 별도로 제안하고, 관리자의 검토를 거쳐 공통 자료에 반영합니다.
03 / 운영 방식

정책은 함께 정리하고,
변경은 검토한 뒤 반영합니다.

자료를 작성하는 단계와 현재 질의응답에 사용하는 단계를 나눴습니다. 임직원의 정책 제안은 관리자 검토·승인과 적용일 확인으로 이어집니다.

01

정책 작성·제안

내용과 적용 조건을 정리합니다.

02

검토 요청

자료를 등록해 승인 대기로 보냅니다.

03

관리자 검토

근거·범위를 확인하고 승인하거나 수정을 요청합니다.

04

적용일 확인

승인 상태와 적용 기간을 확인합니다.

05

이후 답변 반영

적용 시점에 맞춰 검색 근거로 사용합니다.

정책 추가 · 실제 사용 순서

내부 정책을 추가하는 방법

상단의 ‘정책 추가’에서 내용을 작성하고, 검토 요청과 관리자 승인을 거쳐 답변 근거로 반영합니다.

  1. ‘정책 추가’ 열기

    로그인 후 상단 버튼을 누르면 오른쪽 작성 패널이 열립니다.

  2. 제목·내용과 적용 조건 작성

    적용 차종·연식·시행일·종료일을 지정하고, 근거와 예외 조건은 내용에 함께 적습니다. 차종과 연식을 비워 두면 전체 범위로 취급하므로 대상이 맞는지 확인합니다.

  3. 필요하면 파일에서 내용 가져오기

    UTF-8 형식의 .md·.txt 파일을 선택해 본문을 채울 수 있습니다. 파일은 200KB 이하, 본문은 50,000자 이하입니다.

  4. ‘임시 저장’으로 작성본 보관

    작성 중인 자료는 임시 저장 상태이며 답변에는 반영되지 않습니다.

  5. ‘정보 등록하기’로 검토 요청

    등록하면 승인 대기 상태로 전환됩니다. 기존 정책의 수정본도 승인 전에는 현재 적용본을 바꾸지 않습니다.

  6. 관리자가 검토하고 승인

    ‘정책 관리’에서 내용·범위·기간을 확인합니다. ‘승인하고 반영’ 후 ‘관리자 승인 확정’으로 승인하거나 ‘수정 요청’을 보냅니다.

  7. 적용일에 맞춰 새 답변에 반영

    미래 시행일의 정책은 해당 날짜부터 사용합니다. 기존 대화와 저장 답변의 당시 내용·근거는 유지합니다.

엑셀 원장 갱신과 정책 파일 가져오기는 별도 경로입니다.엑셀은 앞의 원장 정리·갱신 절차로 처리합니다. 정책 추가 화면의 파일 선택은 .md·.txt 내용을 입력하는 기능이며 자동 등록·승인을 실행하지 않습니다. 적용 날짜가 ‘알 수 없음’이면 저장·등록은 가능하지만, 날짜를 확인하기 전에는 승인·답변 반영이 차단됩니다.
작성과 답변 반영을 구분

무엇이 바뀌었고,
언제부터 쓰는지 관리합니다.

신규·수정 정책은 승인 전에 답변에 반영하지 않습니다. 승인됐더라도 시작일이 미래라면 해당 시점부터 사용합니다.

기존에 가져온 미검토 원본은 상태를 표시하며 사용될 수 있습니다. 원본·현재 적용본·변경 이력을 구분해 검토할 수 있도록 구성했습니다.

개인 대화와 저장한 답변은 사용자별로 관리하고, 공통 정책의 승인과 변경 관리는 관리자 권한으로 나눴습니다.
